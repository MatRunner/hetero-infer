# 基线性能分析

## 线程数，-t

测试命令：

```bash
./llama-bench -m <model> -r 3 -ngl 0 -t 64,128,192,256
```

这里比较奇怪的地方在于：增加线程数没有提高prefill的性能，而且decode的性能还劣化了。这样就衍生出两个主要的问题：

1. 每次测试的计算量是一定的，增加线程后，算力应该是提高的，预期prefill性能也是提高的，但是为什么没有变化？
2. decode公认为mem bound，增加线程并不会影响多少性能，但是threads=64时性能最好，增加线程后逐步劣化？

### Q1：prefill性能问题

提高线程数prefill性能不变，从cpu利用率上可以观察到，即使分配了64个线程，占用率是远未达到的，也就是非计算瓶颈，因此增加线程并不改变性能。

可以先理论计算一下p512需要的理论算力：Qwen3.8-Q4_K_Medium每次激活6B的参数，根据[理论预测性能](./理论预测性能.md), 一次前向计算量为12GFLOPS*512=6144GFLOPS。按照prefill 77 TOPS来算，512/77=6.6s，每秒的计算量为6144/6.6=930GFLOPS。
